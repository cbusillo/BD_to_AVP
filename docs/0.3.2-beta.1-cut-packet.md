## Focused Product Scope

- PR #576 replaces option-first setup with explicit Ready, Customized, Editor,
  Conflict, and Queue Review states. Profile editing is transactional; route and
  quality conflicts require an explicit answer; remembered decisions can be
  forgotten; and narrow-window and accessibility behavior are covered.
- PR #580 detects MakeMKV in both `/Applications/MakeMKV.app` and
  `/Applications/MakeMKV/MakeMKV.app`, preventing false missing-tool failures for
  the supported nested installation layout.
- PR #583 adds the structured Conversion Setup Beta Test Guide, including full
  Application Support backup and rollback, comparable tester journeys,
  diagnostics guidance, and explicit non-goals.
- The candidate also contains the already-landed durable batch and source-folder
  queue foundations plus release-qualification hardening since Stable `0.3.1`.
  The future first-class queue workspace, scheduling, notifications, storage
  forecasting, history UI, and watch-folder intake remain outside this Beta's
  user-feedback scope.

Issue #542 batch-folder Main Feature versus All 3D Titles selection, issue #438
guided Vision Pro playback, issue #554 broad test cleanup, and unrelated Swift
formatting work are deliberately deferred so feedback remains attributable to
Conversion Setup.

## Reviewed Release-Note Seed

> BD_to_AVP `v0.3.2-beta.1` introduces a repetition-first Conversion Setup for
> real-user testing. The selected Profile, destination, and expected result are
> visible before starting; per-conversion edits are transactional; incompatible
> route and quality choices require an explicit answer; remembered choices can
> be forgotten; and queued sources retain their reviewed decisions. This Beta
> also recognizes MakeMKV installed in `/Applications/MakeMKV/MakeMKV.app` and
> includes resilience improvements for multi-title and source-folder queue
> progress. See the Conversion Setup Beta Test Guide before installing, and back
> up the complete Application Support folder before opening the Beta.

GitHub-generated notes compare with immutable Stable `v0.3.1`. The generated
change list includes release infrastructure and dependency maintenance as well
as product changes; the reviewed seed keeps the updater summary focused while
the generated list preserves full attribution and history.

## Qualification And Authorization

Immutable Stable `v0.3.1` is the prior artifact, release-note base, and update
route input. Preparation may carry only evidence whose mapped paths and
contracts remain clean. Exact same-run signed artifact, installed UI, live
Sparkle, clean-machine, and post-publication evidence remains owned by the
guarded artifact and milestone phases. Missing or due operator evidence stays
visible and cannot become a fabricated pass.

Before dispatch, record the exact protected `main` SHA and establish a temporary
merge hold. Monitor only with `uv run python -m scripts.github_release_run
watch`. If it exits `20`, obtain fresh explicit run-bound authorization in the
active conversation and approve only through `scripts.github_release_run
approve` with the emitted run ID, workflow, full `main` SHA, confirmation SHA,
and approval fingerprint.

This preparation PR does not authorize workflow dispatch, production signing,
environment approval, tag creation, or publication.
