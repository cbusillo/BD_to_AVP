# Real MVC decoder integration lane

`tests/test_native_mvc_integration.py` runs the bundled `edge264_test` on an
external clean MVC bitstream and an external damaged-right-view bitstream.
Ordinary CI skips this lane when `BD_TO_AVP_MVC_FIXTURE_MANIFEST` is unset.
Setting it opts in; missing files, missing tools, incorrect input digests,
decoder failures and timeouts then fail rather than skip.

The checked-in [reference manifest](../tests/fixtures/native-mvc-manifest.json)
contains immutable fixture identities and accepted output hashes, **no media**.
The clean fixture is the JVT MVC conformance vector `MVCDS-4`; the damaged
fixture is upstream's synthetic `mvc_corrupt_dep_slice` regression reproducer,
which corrupts a right-view slice header. This is a decoder regression lane,
not a commercial-title or physical-headset acceptance test.

Both fixtures are pinned to the revision recorded in the manifest. Clean-eye
SHA-256 references were captured from raw planar YUV420 output and cross-checked
against both per-eye FNV hashes in that revision's
[`tests/conformance/manifest.txt`](https://github.com/jens-duttke/edge264-mvc/blob/44e30b66d43a17418e0b342eba54d69d0c3be829/tests/conformance/manifest.txt).
The [upstream provenance](https://github.com/jens-duttke/edge264-mvc/blob/44e30b66d43a17418e0b342eba54d69d0c3be829/tests/conformance/README.md)
anchors the base view to the ITU reference and the dependent view to validated
decoder output. The references are never regenerated by the test or derived
from the decoder under test.

## Run the gated lane

From a repository checkout with the usual `uv sync --all-groups --python 3.12`
setup and configured FFmpeg, put the fixtures outside the checkout. On
Chris-Studio, use a directory on Developer-Artifacts:

```sh
mvc_fixtures=/Volumes/Developer-Artifacts/task-evidence/BD_to_AVP/mvc-integration
mkdir -p "$mvc_fixtures"
cp tests/fixtures/native-mvc-manifest.json "$mvc_fixtures/manifest.json"
mvc_revision=$(uv run python -c 'import json; print(json.load(open("tests/fixtures/native-mvc-manifest.json"))["provenance"]["revision"])')
curl -fsSL "https://raw.githubusercontent.com/jens-duttke/edge264-mvc/$mvc_revision/tests/conformance/mvc/MVCDS-4.264" -o "$mvc_fixtures/clean.264"
curl -fsSL "https://raw.githubusercontent.com/jens-duttke/edge264-mvc/$mvc_revision/tests/liveness/mvc_corrupt_dep_slice.264" -o "$mvc_fixtures/damaged.264"
BD_TO_AVP_MVC_FIXTURE_MANIFEST="$mvc_fixtures/manifest.json" \
  uv run pytest -q tests/test_native_mvc_integration.py
```

The test itself is offline. Provision the external files separately on any
runner that enables the lane; no CI download or media redistribution is added.
Another accepted fixture bundle can use the same manifest fields: `clean` and
`damaged` each specify `stream` (relative to the manifest, `.264`),
`stream_sha256`, per-eye `width`/`height`, `frames`, and `frame_rate`. `clean`
also requires distinct `left_sha256` and `right_sha256` of complete planar
YUV420 outputs in display order. Accept those references independently before
using the bundle; do not bless new output just because the current binary emits it.

## What fails

The lane checks single- and multithreaded decoding, exact nonzero frame counts,
and equal left/right counts. It executes the graph and maps from
`generate_native_mvc_ffmpeg_command`, replacing only lossy encoding options
with raw YUV output so hashes can detect eye swaps, frame reordering and changed
pixels. Clean decoding checks both normal eye order and the user's swap-eyes
option. Damaged decoding must finish, emit a skip position recognized by the
production damage collector, and produce a user warning.

The lane covers the generated left/right path named in #842. Direct MV-HEVC
normalization and AV1 packing use separate commands and are outside this lane.
It runs decoder and FFmpeg sequentially; it does not qualify concurrent pipe
coordination, the production stall detector, or retry/fallback behavior.

Each decoder and FFmpeg invocation has a 30-second timeout. Decoder output goes
to a temporary file, avoiding pipe backpressure and allowing its exit status to
be checked independently of FFmpeg. `subprocess.run` kills and reaps a timed-out
process; temporary outputs are cleaned up even on failure. This tiny reference
bundle normally runs well under 10 seconds; larger private fixtures remain in
this gated lane.

Planted-fault evidence belongs in the pull request: invert the production eye
mapping, drop a decoded frame, suppress the decoder's damage warning, or run a
decoder with the damage-skip guard removed. The relevant test must fail; restore
the original code before the full suite and commit. A bounded sleeping decoder substitute
can additionally verify timeout handling, but is not evidence that a real
decoder regression was reproduced.
