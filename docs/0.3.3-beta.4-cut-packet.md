## Candidate Identity

- Owner: issue #779.
- Package version: `0.3.3b4`.
- Public version: `0.3.3-beta.4`.
- Tag and release name: `v0.3.3-beta.4`.
- Build: `175`.
- Route: `Prerelease` / Sparkle `beta`; GitHub prerelease; not Latest; PyPI and
  Homebrew publication disabled.

This candidate converts a 3D source whose right-eye (MVC dependent-view) video
has a damaged frame. The bundled edge264 splitter rejects the corrupt slice
before it alters decoder state, fills the damaged right-eye frame in from the
left eye of the same access unit, and reports the position. The app shows a
non-blocking warning that names the source time to inspect. Worker protocol 13
and the Beta 3 stall notice with its Keep Waiting and Stop controls are
unchanged. No automatic remux or retry is added: the damage is in the encoded
video, which a remux copies unchanged.

The reporter's file from issue #771 was used for verification. Through the
fixed splitter the full title decodes 196,216 of 196,216 frames with one skip
reported at 01:30:00; a 40-second clip around the damage converts end to end
with the warning. The decoder change is also proposed upstream as
jens-duttke/edge264-mvc#12; this candidate pins the fork revision
`3f7d1eaa922b23fc1b8f43f3812c657dbf8f374a`.

This is the first candidate built with Xcode 27.0 build `27A266a` on GitHub's
`xcode-27` image. The compatibility job remains on macOS 26. Signing,
notarization and the signed installed-UI check run on the new toolchain for the
first time in this release. Movie Sharing remains compatible with **Shiny 3D
Cinema 0.1.0 (3)**; see the [Movie Sharing beta quick start](movie-sharing-beta.md).

Post-dispatch source SHA, signed DMG and app-tree checksums, release run, release
ID and appcast checksum remain unset in preregistration. Record those facts only
from the guarded release's immutable receipts.
