This candidate fixes long conversions that failed when the display slept.
Since Beta 3 the worker treated ten seconds of event-pipe backpressure as a
failed stream. macOS throttles an app whose display sleeps, so the Mac app
stopped draining the pipe and a healthy conversion ended with "The app stopped
receiving progress updates." The app now holds an activity assertion for the
life of every worker job, and the worker skips superseded heartbeat and
observability records when the pipe has no room while ordered records wait up
to fifteen minutes. A closed pipe or a torn record still fails immediately with
exit 74. Worker protocol 13 and every record shape are unchanged.

The bundled edge264 splitter is pinned to upstream `jens-duttke/edge264-mvc`
revision `67565bc79da3b82c8aa25d64094b9c5f18dbf36c` (`v2026.09.19-2`), which
contains the corrupt dependent-view slice fix first shipped in Beta 4 and an
upstream `idr_pic_id` stall fix. On the damaged window of the file from issue
#771 this binary produces output byte-identical to the Beta 4 decoder.

The owner converted the full 2h16m title from issue #771 in the app, unattended
overnight with the screens off; an earlier run converted all 196,216 frames
with the display off for part of it. Movie Sharing remains compatible with
**Shiny 3D Cinema 0.1.0 (3)**; see the
[Movie Sharing beta quick start](movie-sharing-beta.md).

Post-dispatch source SHA, signed DMG and app-tree checksums, release run, release
ID and appcast checksum remain unset in preregistration. Record those facts only
from the guarded release's immutable receipts.
